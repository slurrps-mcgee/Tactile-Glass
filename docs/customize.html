Theming

Customize

Color modes live in one sheet: src/scss/base/_themes.scss. Light is the full palette on :root. Dark is a patch — only the tokens that change. Structural values (type, radii, blur) stay on light.

1. Global :root

:root {
  --tg-primary: #c084fc;
  --tg-primary-rgb: 192, 132, 252;
  --tg-body-bg: #c8c2d4;
  --spacing: 0.25rem;
  --radius-md: 12px;
  --font-sans: "Inter", system-ui, sans-serif;
  --tg-neu-shadow-drop: 8px 8px 16px #a6a6a6, -8px -8px 16px #e0e0e0;
  --tg-glass-blur: blur(24px);
}

Keep the matching *-rgb channel in sync. Light and dark palettes live in src/scss/base/_themes.scss. btn-dark uses --tg-dark (always a dark fill), not page ink.

CSS variables catalog

Public API is --tg-{name} from the light map in src/scss/base/_themes.scss, plus structural tokens in _tokens.scss. --clr-*, --glass-*, --hybrid-*, and --neu-shadow-* are aliases of those --tg-* values. Dark mode only patches ink, canvas, shadows, and glass/hybrid fills — pastels inherit from light.

Sass

Compile from the package entry. Partials are loaded with @use in a fixed order from tactileglass.scss.

@use 'tactileglass-css/src/scss/tactileglass.scss';

Override tokens after import with CSS variables (preferred), or fork theme maps in base/_themes.scss and recompile:

  • $tg-theme-light / $tg-theme-dark — color modes
  • $tg-colors — semantic utility / component palette
  • $tg-breakpoints + tg-infix — responsive utility generation

There is no Bootstrap-style $enable-* option map yet; carve unused layers by forking the entry @use list if you need a smaller sheet.

Optimize

  • Ship dist/tactileglass.min.css in production (npm run build).
  • Purge unused selectors with your bundler / Lightning CSS / PurgeCSS — class names are static Bootstrap-style strings.
  • Prefer CSS variable overrides over duplicating component CSS.
  • Optional: compile a custom entry that drops unused component partials (alerts, pagination, …) if your app never uses them.
